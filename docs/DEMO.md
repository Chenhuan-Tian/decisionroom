# Three-minute walkthrough

Use a reading-club decision to keep the demonstration concrete. Do not present the landing's illustrative sources as actual evidence.

1. Create a room: “Which book should our reading club choose next?” Two or three options, four-week constraint.
2. Open an ordinary room URL in a second signed-in account to show it is private. Generate an invitation, join through that link, and save a real publisher source with a short contextual note.
3. Change a vote in the second account. Show it updating in the host account without a reload and still counting once.
4. Search once as host, review a result and save it. Generate a comparison. Click a citation to return to the saved source; explain the difference between validating an ID and verifying a claim.
5. Add another evidence card and show that the old comparison is stale. Regenerate it or explicitly make a manual decision.
6. Enter the final rationale, review it and confirm. Show the frozen room and export its brief.
7. If Calendar has been manually verified, show the confirmation form and the existing review event. Do not create a disposable real event merely for a screen recording without deciding who will manage it.

## Explain without the agent

- Why is a client-side room filter insufficient? Where does native `teamField` filtering happen?
- Why are record writes action-only? Which identity is authoritative for votes and hosts?
- What happens if a vote and finalization race?
- What makes a comparison stale, and what does the citation validator fail to prove?
- What happens after Calendar accepts an event but its response is lost?
- Why do other rooms continue while one room waits for AI?

## Useful live changes

Practice changing one meaningful rule, then update its test: add a reason to votes, change the evidence cap, or require at least one evidence card before finalization. Explain the impact on existing data and the product before editing.
